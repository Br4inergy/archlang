# Agent integrations

ArchLang ships one skill source, `skills/<name>/SKILL.md` (the umbrella `archlang` skill and four task
skills), and publishes it in the shape each agent host reads. Every file below is generated by
`npm run gen:agent-manifests` and gated by `npm run check:drift`; edit the skill or `src/manifest.ts`,
never the output. No generated manifest names a version or a count, so none can go stale; hosts read
the repository's own tags and releases.

Formats were taken from each host's own documentation on 2026-10-13; the source URLs are in the header
of `scripts/gen-agent-manifests.ts`. The Claude Code plugin is covered by [`gen:plugin`](overview.md)
and is not repeated here.

| Host | Generated files | Where the host finds them |
|---|---|---|
| Codex and ChatGPT | `plugin.json` (portable Agent Plugins manifest), `.agents/skills/<name>/SKILL.md` | the repository root; Codex scans `.agents/skills` from the working directory up to the repository root |
| GitHub Copilot (CLI and cloud agent) | `plugin.json`, `.agents/skills/<name>/SKILL.md`, `integrations/copilot/*` | Copilot reads project skills from `.github/skills`, `.claude/skills` or `.agents/skills` |
| Cursor | `.cursor-plugin/plugin.json`, `integrations/cursor/archlang.mdc` | the repository root (plugin); the rule is a copy-in file |
| Any Agent Plugins client | `plugin.json` | the repository root; skills are found in the root `skills/` directory |

## What the files are

- `plugin.json`: the portable Agent Plugins manifest (`$schema` `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json`).
  Identity fields only (name, description, author, homepage, repository, license, keywords); the skills
  are found in the root `skills/` directory, so there is no `skills` field.
- `.cursor-plugin/plugin.json`: the Cursor plugin manifest. Cursor requires only `name`; it discovers
  `skills/` by default.
- `.agents/skills/<name>/SKILL.md`: byte-identical copies of the five skills, in the project-skill
  directory that both Codex and Copilot scan.
- `integrations/cursor/archlang.mdc`: a Cursor rule scoped to `**/*.arch`.
- `integrations/copilot/copilot-instructions.md` and `integrations/copilot/archlang.instructions.md`:
  Copilot custom instructions (repository-wide, and path-specific with `applyTo: "**/*.arch"`).

None of these configures the MCP server: the manifests carry skills, and the MCP server is installed
separately (`npx -y @chanmeng666/archlang-mcp`) or through the Claude Code plugin.

## How a user installs them

- **Codex / ChatGPT:** in a clone of this repository the skills load from `.agents/skills`. To use them
  in another project, copy `.agents/skills/` into that project (or into `~/.agents/skills` for every
  project). Once the plugin is listed in the directory: open the Plugins tab and search for ArchLang.
- **GitHub Copilot:** copy `.agents/skills/` (or `.github/skills/`) into the project, and optionally
  `integrations/copilot/copilot-instructions.md` to `.github/copilot-instructions.md` and
  `integrations/copilot/archlang.instructions.md` to `.github/instructions/`. Once the plugin is listed
  in Awesome Copilot: `copilot plugin install archlang@awesome-copilot`.
- **Cursor:** copy `integrations/cursor/archlang.mdc` to `.cursor/rules/`; for the skills, clone the
  repository into `~/.cursor/plugins/local/archlang` and reload the window. Once listed: install from
  the Cursor Marketplace.
- **Anything else:** `npx skills add ChanMeng666/archlang` installs the same skills for the hosts the
  `skills` CLI supports.

## Owner-only submission

An agent never creates an account, types a credential, accepts terms or submits a form (see
[`seo.md`](seo.md) section 8). Every step below is the owner's, by hand. Status of all three: prepared,
not submitted.

### OpenAI plugin directory (Codex and ChatGPT)

1. Sign in at <https://platform.openai.com/plugins> with an organization-owner account (or a member with
   Apps Management Write) and complete the individual or business verification in organization settings.
2. Choose **Upload new or existing plugin** and upload a ZIP of the plugin: `plugin.json` plus `skills/`.
   The directory's Codex checklist also asks for `version`, `author.name`, `capabilities` and a
   `composerIcon`, and the portal collects `displayName` (30 characters or fewer), `shortDescription`
   (30 or fewer), `longDescription`, `developerName`, `category`, an icon and HTTPS website, support,
   privacy-policy and terms-of-service URLs. The generated `plugin.json` deliberately has no `version`;
   add the release tag's version in the ZIP, not in the repository.
3. Resolve the automated Metadata and Skills findings, then fill in the review form: five positive and
   three negative test cases and a reviewer-accessible video URL. Submit for review and attest to the
   policies.
4. After approval the owner chooses when to publish. The portal does not currently accept
   `.app.json` references or lifecycle hooks; the ZIP has neither.

### Awesome Copilot (GitHub Copilot CLI marketplace)

1. Do not edit `plugins/external.json` in `github/awesome-copilot`: its contributing guide routes
   external plugins through an issue form. Open a new issue in <https://github.com/github/awesome-copilot/issues/new/choose>
   from the owner's GitHub account and choose the external plugin form.
2. Give it the repository URL `https://github.com/ChanMeng666/archlang` (public GitHub hosting is the
   only source accepted), the plugin name `archlang`, and the description from `plugin.json`.
3. If a maintainer asks for a native entry instead, the contribution format is
   `plugins/<plugin-id>/plugin.json` with a `README.md`, validated by `npm run plugin:validate`; an
   AI-authored pull request must end its title with the markers that guide names.

### Cursor Marketplace

1. Sign in to Cursor with the owner's account and open <https://cursor.com/marketplace/publish>.
2. Submit the repository `https://github.com/ChanMeng666/archlang` (plugins must be open source and are
   distributed as Git repositories); the manifest it reads is `.cursor-plugin/plugin.json`.
3. Cursor reviews every plugin and every update by hand before listing it. Follow its submission
   checklist at <https://cursor.com/docs/reference/plugins>.

Listing counts, ratings and install numbers on these hosts measure usage, not revenue, and are quoted
nowhere in this repository.
