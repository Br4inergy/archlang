# 00 · 深挖方向的重要程度排序与依据

> 日期：2026-10-23（v0.5 于 2026-10-24 同步：Q17–Q22 已全部由所有者决定；v0.6 于 2026-10-24 在 `main@1a1efd9` 重核方向 1 的核心契约，见 [`01`](01-core-contract-and-input-channel.md)）· 对应主文档 v0.6 · 本目录是 [`development-plan.md`](../development-plan.md) 的**研究附件**：主文档给结论与决策，这里给证据、方案比较与未验证项。

## 1. 排序依据（写下来，方便被质疑）

重要程度 **S = I × U × B**，三项各按 1–5 打分：

| 因子 | 含义 | 1 | 5 |
|---|---|---|---|
| **I** 影响 | 做错了对项目成败的影响 | 只影响体验细节 | 方向性错误或整体返工 |
| **U** 不确定性 | **深挖前**我们对它掌握多少 | 已有实测或规范明确 | 没有任何证据 |
| **B** 阻塞性 | 它阻塞多少后续工作 | 不阻塞 | 阻塞 M0/M1 的主路径 |

打分是我的判断，不是测量；用来决定"先挖什么"，不是结论。**U 取深挖前的值**——排序回答"为什么先挖它"，"深挖后剩余的不确定性"另列一列。并列时 B 大者靠前。

## 3. 各方向一句话结论

1. **核心契约**：通道 A 必须多导出 `resolvePlan`（`compile().ast` 未链接，对带 import 的平面静默丢元素）；C1 类型闭包——v0.4 写作"10 个直接类型 + 2 个门词汇类型"，**v0.6 在 `main@1a1efd9` 用与核心 `public-surface` 测试同法的脚本重推导并更正为 13 个类型 + `AnalyzeOptions`**（旧脚本少算 `JoinableWall`、`Edge`）；→ **Q18（已决定，2026-10-24）**。
2. **墙体几何**：H1 **成立**，机制是 `split.faceOf = id`（不是分组键）；45 个平面零空所有权、体积精确；夹点与切口跨片需要"每连通片一个实体、对每个被覆盖片开洞"；混合高度有 1.6% 的合成缺块，示例里 0 例 → **Q19（已决定：接受并告警）**。
3. **IFC**：自研最小写入器（原型 117 行）在 43 个平面上 0 校验问题、逐字节确定、体积 −0.14%；`@ifc-lite/create` 干净且可确定，但高层 API 做不了弧墙/洞口；IfcOpenShell 对弧墙共面切口**静默失败**，需 20 mm 外扩 → **Q17（已决定：Q4 判据补一条几何保真）**。
4. **垂直/屋顶**：8 个示例的屋檐环全是矩形（凹环 0 个）；3/5 个可推导楼梯合规，另 2 个坡度本身超限；`straight-skeleton@3` 实质是 GPL 的 CGAL，应排除；纯 TS 的 1.1.0 对共线与近圆多边形不可靠 → M3 重估为 14/7 → **Q22（已决定：生成并告警，不拒绝）**。
5. **渲染**：Blender CPU 与无头 three.js 在同机上都**逐像素可复现**（PNG 文件字节不同，须比像素）；耗时 4–12 s 与 0.04 s；跨机器未测 → **Q21（已决定：钉死 Chrome 的无头 three.js 为 CI 判据，Blender 不阻断）**。
6. **资产**：83 家族/129 词；前 30 个家族覆盖 91.1% 的使用；卫浴（`wc`+`basin`）是最常用且最需曲面的，而 Poly Haven 一个卫浴模型都没有。
7. **Agent/工程**：核心侧三项合计 ≤ 15 ms/平面；npm 的 `license` 字段会放过"标 MIT 实为 GPL"的包，L1 须强化 → **Q20（已决定：强化）**。

## 4. 诚实说明

- 所有"实测"都在**一台** 8 核、无 GPU 的 Linux 机器上，单次实验，非基准；"读码"指读源码而未运行；"待核实"指没有证据。
- 压力平面是我写的合成样本；A/B/C 家具分类、楼梯判据的中点（625 mm）、顶点数阈值（24）都是**建议值**。
