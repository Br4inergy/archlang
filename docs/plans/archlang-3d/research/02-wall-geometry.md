## 1. 问题定义

3D 的墙需要**每面墙一个实体**（才能给 IFC 的 `IfcWall`、glTF 的命名节点、逐墙材质/高度/洞口）。核心的 `joinWallSet` 给出的是"按填充图案合并的整体轮廓"。H1 问：能否从核心的连接结果里取出**每面墙独占的多边形**，并且：

1. 拐角/T 型/十字/锐角处不重叠、不留缝；
2. 弧墙、斜墙及其上的门窗可用；
3. 拉伸成棱柱后水密、体积正确；
4. 洞口切割落在正确的墙上；
5. 同一层里墙高不同（混合高度）时仍然正确。

## 2. 当前证据

### 2.1 机制：用 `split.faceOf`，不是分组键 [实测+读码]

`joinWallSet(walls, groups, { faceOf: w => w.id, faces: ids })` 之后，`result.split.fills.filter(f => f.face === id)` 即墙 `id` 的所有权环。**`group` 来自 `hatchKey(hatchOf(w))`、调用方不可设**，所以主文档原 H1 的"以 `id` 作分组键"措辞作废，改为"以 `faceOf = id` 拆分"（核心的 `wall-lowering.ts`、`analyze/wall-faces.ts` 已在用同一机制，见 [`01`](01-core-contract-and-input-channel.md) §2.4）。

所有权规则是核心的"最厚者拥有，同厚按下标"（`byOwnership`）；`thickness` 只用于所有权、平局规则与预筛半径，**不**用于高度。

### 2.2 全量结果（34 个示例 + 11 个合成压力平面 = 45 个平面）

> 口径说明：`h1_prism_check.mts` 覆盖全部 45 个平面（含 `imports`、`museum-wings`）；`h1_wall_ownership.mts` 的虚拟世界没有放进 `museum-wing.arch`，`museum-wings` 在它里面报 `no-ir`，所以它的统计（空所有权、超带、拼合误差、耗时、弧/斜墙计数）基于 33 个示例，不含压力平面。

| 指标 | 结果 |
|---|---|
| 墙 / 所有权棱柱 / 连通片 | 311 / 309 / 329（差的 2 面墙在 `s8`：3 面完全重叠的同形墙只有 1 面拥有面积，**预期**）|
| 示例里"所有权为空"的墙 | **0** |
| 所有权区域超出自身墙带 | **0**（slots 与 solid 两种模式）|
| 拼合误差（所有权区域之并 vs 整体轮廓）| 直线墙 **0**；含弧时 ≤ **4.8×10^-4**（相对，来自弧离散）|
| `joinWallSet` 耗时（33 个示例，含 `split`；两次运行）| slots 模式最大 9.6 / 7.0 ms，solid 模式最大 3.8 / 4.0 ms（单机，有抖动）|
| 洞口切口 | 520 个；**3 个**的质心落在宿主墙自己的片之外（见 §2.4）|
| 棱柱（earcut 三角化的盖面 + 侧面）面积/体积 | 与"环面积 × 高"一致（误差 0）|
| 水密（按连通片检查开放边）| 总开放边 6，全部来自 1 个片：`library.arch` 的 `w_drum`（圆形鼓墙在切点处自接触，6 条开放边）；整墙不拆片时 `aquarium` 2、`library` 12 条——**两个片只在一点相接（夹点）**，把每个连通片当作独立实体即可消除 |
| 示例里有弧的墙 / 其上有洞口 / 斜墙 | 5 / 5 / 6 |

两种模式：**slots**（洞口作为全高槽先切掉，门窗上下墙段另算）与 **solid**（先去掉洞口得实心所有权，再单独处理切口）。M1 采用 solid：实心所有权稳定，切口作为单独对象交给 §4.3 与 IFC 的 `IfcOpeningElement`。solid 模式下少数墙因 T 型接头被分成多个连通片（11 个平面里出现），**每个连通片一个实体**。

### 2.3 弧墙与斜墙 [实测]

- 库通道的弧是**精确**的（`Edge`），弧墙所有权环含弧段。spike 里 IoU 最差的 0.46 来自 **Plan JSON 通道丢失弧**，不是库通道的问题——这再次支持主通道用库 API。
- 弧墙/斜墙上的门窗：压力平面 `s5-door-on-arc`、`s10-angled-door` 均可编译、可切口；`s6`（20° 锐角）、`s3`（Y 型 60°）、`s2`（十字）、`s1`（T 型）的棱柱开放边为 0、面积与体积和环一致（`s9` 窄缝平行墙、`s7` 共线异厚同样为 0）。

### 2.4 洞口切口跨片 [实测]

520 个切口里 **3 个**（全在 `library` 的鼓墙：切点处两面等厚墙相接）质心落在宿主墙自己的片之外。含义：**切口必须对它覆盖的每一个片挖洞，而不是只对宿主**。IFC 一个 `IfcOpeningElement` 只能开一个构件，所以要"每个被覆盖的片一个开洞"（见 [`03-ifc-output.md`](03-ifc-output.md)）。

### 2.5 混合高度 [实测，仅合成]

- 34 个示例里**没有**同一层内墙高不同的平面（`heightsPerStorey` 每层只有一个高度；不同层才不同，如 `two-storey` 2700/3000）。
- 合成 `s11-mixed-thick-low`（厚而矮的墙穿过薄而高的墙）：最厚者拥有 ⇒ 矮墙占了交叉处，高墙在交叉处**缺一块**，体积误差 **1.62%**（0.054 / 3.342 m³）。
- 把所有权改为"高者优先"（直接调内部 `joinWalls` 并把 `thickness` 伪造成 `height×10^6 + thickness`）误差 **0**。结论：需要一个**所有权优先级**钩子才能干净地解决；这与核心 backlog V.1（混合高度接头互相穿插，won't-fix）一致——核心不会替 3D 修。

## 4. 推荐与理由

- **H1 判为成立**，退路（+3 人天）**取消**。依据：45 个平面零空所有权、零超带、棱柱体积精确、join ≤ 10 ms。
- 按 S1 + P1 + O1 实现；混合高度走 H-a 并写进 V-GEO 检查（`W3D_MIXED_HEIGHT_JOINT`，用 `s11` 作回归），**不阻塞**。**Q19 已由所有者于 2026-10-24 决定：采用 H-a**（接受并告警）；H-b 仅在出现真实的混合高度平面时再提给核心（非阻塞）。

## 5. 风险与未验证项

- 压力平面是我写的合成样本，**不代表所有真实平面**；尤其"斜墙 + 弧墙 + 洞口跨接头"的组合只测了单点情形。
- 开放边检查用的是自写的"每条边被两个三角形共享"判据，不等于完整的流形/自交检测（未做自交检测）[待核实]。
- 洞口切口"覆盖哪些片"用格点采样判定，极窄切口可能漏判 [待核实：改为精确多边形相交后再测]。
- 弧的离散步长沿用核心 `ARC_STEP_DEG = 7.5`；3D 里更细或更粗的取舍（面数 vs 平滑度）未评估。
- 性能数据来自单机单进程，非基准。
